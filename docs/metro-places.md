# 東京三帯の Places

「渋谷のスクランブル交差点をスポーン位置にしたように、Places に各地をリストしたい」
という依頼に対応。PC・スマホの Places に16地点を並べ、Go now で地上へ移動する。
VRは同じ16地点を8件ずつ2ページに表示する。別の居住環境へ切り替えると従来の行き先へ戻る。

渋谷スクランブル交差点、皇居・竹橋、東京、新宿、池袋、中野、水道橋、王子、練馬、
川口、南浦和、浦和、さいたま新都心、大宮、岩槻、蓮田。
皇居は竹橋付近の道路へ到着し、駅は建物内部でなく周辺の道路へ到着する。
初期スポーンの渋谷と、既存の5地点の到着座標は変更していない。

## 到着位置

`assets/plateau/prepare_metro_places.py` が N02-25 の駅位置、PLATEAUの道路用地・建物、
水面、GSI地形を使い `src/worlds/generated/metroPlaces.json` を作る。
道路端から0.75m、建物から0.6m、水面から0.5mを避け、元データ上で65m以上の連続した
経路がある位置を採用。参照点からの移動は0〜96.1m。元タイルや衝突面は加工しない。
地理フレーム・半径・長さが一致する世界だけでカタログを有効にし、別の切り出し範囲に
東京の座標が流入しないようにした。既存の到着準備ゲートで景観と衝突を待ってから移動する。

再生成例（出力先は明示する）:

```sh
python assets/plateau/prepare_metro_places.py \
  --root /Volumes/BLAZE/Spinward/inland-b-20260924 \
  --output /Users/toming/keel/lake/spinward-development/src/worlds/generated/metroPlaces.json
```

## 検証証跡

`/Volumes/BLAZE/Spinward/inland-b-20260924/places-20260925/` に固定buildと画像・計測を保存。
採用buildは `main-dist-v2`。UIの単体検査に加え、`qa/plateau/metro-main.xr.mjs` に
PC全16地点の実ボタン操作、描画三角形への接地、短い歩行、スマホ末尾へのスクロール、
VRの2ページから三帯への移動と渋谷への帰還を追加した。
VRはplaywright-webxr 0.3.0、ハードウェアGPUでのエミュレーション。実HMDは未検証。

初回候補では新しい地点の案内カードが未登録で例外が発生したため、同じカタログから
カードも生成し、全行き先の通知を単体検査に含めた。VRの描画例外はconsoleにも出るため、
pageerrorだけでなくconsoleの例外も検査する。PCでは同じ渋谷への再移動で古い状態を
読まないよう、行き先イベントの反映後に接地を測る。接触の許容値は緩めていない。

`qa-v2` はスマホ、VR Places、VRの全プリセット往復が成功。PC全地点検査の待ち条件を
修正した再実行は `qa-pc-final`。画像のみの独立レビューでは、PC末尾ボタンの見切れと
スマホ固定見出しの透けを修正し、VR両ページの長い日本語名も欠けずに収まることを確認。

最終結果: PC全16地点と定常フレーム検査が成功。各地点で1.36m以上歩行でき、描画面と
物理接地高さの差は最大0.037m。関連36単体検査・型検査・317モジュールのbuildも成功。
検証済み版を5318のローカルプレビューへ反映した。公開・pushは行っていない。
