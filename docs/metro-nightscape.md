# PLATEAU街区の夜景と航空障害灯

2026-09-25、tomingの「夜景がイマイチ？」は、駅だけでなく街・コロニー全体への指摘。
駅外観の追加とは別の照明接続が必要だった。街路・窓・遠景の夜景と航空障害灯を実装し、
同日、通常プレビュー5318へ反映・動作確認を完了した。実機HMDは未検証。

## 2026-09-25 実装と検証の現在地

夜景全体のゴールと、tomingの追加依頼「航空障害灯も付けてほしい」を実装した。
通常URLは `http://127.0.0.1:5318/?city=tokyo&preset=izma`。
大宮の夜は同URLへ `&place=omiya&t=.02` を加える。候補5319は検証後に停止。

### 配置と固定上限

- PLATEAU道路の結合境界とDEMから三帯140,316組の街路灯を設計。建物1.1m離隔、水面、
  幅5.5m未満の道、急な段差、18m未満の重複を除外。これは設備の実測復元ではない。
  座標3,928,848 bytes、表示は近傍最大512組。実ライトは従来のQuest 1灯／desktop 2灯を再利用。
- 近景は共通窓レシピの色・点灯を保ち、眼ごとの光線から浅い室内の明暗を計算する。
  住宅の住戸別色温度、オフィスの白色と階ごとの消灯、駅・店舗の用途を共有する。
- 中景は同じ実窓10,841,699枚を10,200タイルに生成し、各帯8MiB／80タイル／取得1本で配信。
  全域435MBを一括常駐しない。実建物の詳細面がある場所だけ表示し、低精度の箱へ窓を浮かせない。
  近景140〜280mで受け渡し、1.3〜2kmで面積平均へ収束。看板は窓の遷移で消さない。
- 三帯の遠景路面・窓平均画像はRGBA＋mipmapで42.52MB。地面の近傍120mは256×256・1m刻みの
  照明画像で補う。8m移動か光源変更時だけ更新し、三帯合計0.75MiBのGPU画像を追加する。
  店舗の発光位置・色・点灯から最大128件を選び、壁の背後へ光を投影しない。
- 航空障害灯2,672個。高さ60m以上をSpinwardの配置対象とし、最上部の実屋根三角形へ
  45cm内寄せした支柱を置く。60mはゲーム内設計値で、設備実測や法令適合の主張ではない。
  全域の赤い点は32,064 bytes、650m以内の支柱・灯体は最大128組。実ライト追加は0。
  昼は器具、夜は赤色灯。三帯の曲面変換を屋根・支柱・灯体で共用する。

### 検証で見つかった欠陥と対応

- v2: 8mの路面画像だけでは狭い道路が暗い／東京の無窓面が白く光る。近景照明と、
  詳細建物の遠景平均を1.3〜2kmに限定する処理で修正。独立画像レビューで確認。
- v4: 中景の窓と既存の簡略ファサードが1mm差で重なり、斜めの欠けが出た。
  外向き12cmとpolygon offsetへ変更。東京・大宮の欠け消失を独立レビューで確認。
- v5: 16街路灯＋16店舗を各ピクセルで計算すると、大宮のp95が約33msから50msへ悪化。
  v7で小さな照明画像へ置換しp95は約33msへ戻ったが、その時点では地上平均の増加が残った。
  v8は窓の毎フレーム更新を全タイル走査から常駐最大80件に絞った。
  v10は低層建物の待ち行列も常駐／要求分へ限定し、消灯窓の室内計算を省いた。
  v12は全域の診断情報だけを5Hzへ間引いた（準備完了・衝突等の実判定は即時）。
  v13は全キット456三角形の外向き法線を確認し、外観部品の裏面描画を除去。
  全7部品は幾何学的に閉じた形状で、境界辺・不正接続辺は0。
  最終4地点のbefore→after→beforeで、継続的なフレーム時間の悪化がないことを確認した。
- v8の録画レビューで中距離の窓が建物面ごとに一斉出現。v11は窓データの先読み時ではなく、
  実建物の詳細面が現れてから0.5秒で点灯するよう変更。渋谷の2群を10fpsのcropで比較し、
  段階的点灯への修正を独立レビューで確認（確信度.98）。建物自体の形状LOD切替は残る。
- 長いVR試験の途中で180秒の昼夜周期が夜明けへ進み、夜のassertionが失敗した。
  現在の検証は通常のDay Cycle操作で時計を停止し、同じ夜を比較する。
  本番の時間進行は変更していない。
- v14: 夜景画像の取得が遅いとき、代替表示が準備できるまで元の近景窓の発光を維持。
  取得を意図的に止めても徒歩を妨げず、解放後は新しい夜景へ遷移することを実ブラウザで確認。
- 通常URLのsmokeでローカル `/metric` の404を検出。QAプレビューだけでPOSTを204として
  受け流す処理を追加した。記録・外部転送はせず、本番の利用統計処理は変更していない。

## 採用した方針

1. **街路の光を接続する。** 元道路・歩道・DEMから柱を置ける場所を決め、交差点や建物を避ける。
   見える灯具と光の位置を共有する。路面の明るさはタイル単位の軽い表現にまとめ、
   近傍の壁や身体への光だけを既存の少数の実ライトで補う。
2. **窓を面一枚の発光から改善する。** 天井付近と室内奥で明暗を分け、ガラスや枠を残す。
   住宅の住戸別色温度、オフィスの統一した白色と階単位の消灯は維持する。
   駅・店舗・一般住宅で、夜の明るさの役割を分ける。
3. **遠景にも光を引き継ぐ。** 近景と同じ用途・点灯情報から粗い夜景表現を作る。
   LODで光が急に消えず、遠くでは点群・明暗のまとまりに収束するようにする。
   小さな窓や線の激しい点滅・モアレは、解像度に応じた平均化で抑える。

目標は、地上では灯具・店舗・窓が街路を形づくり、対岸では街区の光がつながって見えること。
全体露出を上げて均一に明るくするだけでは達成できない。

検証は地上、頭上・対岸、昼夜の切替、歩行・高速飛行、VR両眼を同じ地点で比較する。
光源の常駐上限、ロード時間、描画費用を改修前後で測り、従来の高速移動の滑らかさを維持する。
