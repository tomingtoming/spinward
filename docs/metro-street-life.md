# 用途と暮らしが伝わるPLATEAU街路

目標は、現行三帯を歩いて住宅・集合住宅・オフィス・店舗の違いを読み取れること。
前段の[共通外観](metro-building-facades.md)へ、近景の奥行き、入口、夜間照明を追加する。
PLATEAUの用途・輪郭・高さは保持し、以下の意匠はSpinwardの設計として扱う。

## 配置と共通部品

- Blender MCPの別プロセスでkit v3を生成。元のv2原本を保持し、7番目の共通部品としてベランダを追加。
  幅だけを伸縮し、奥行き約0.96m、床厚17cm、腰壁と上部手すり、左右の袖壁を一つの60三角形の部品にする。
- 一部の集合住宅（french-guards構成）の道路側、2階以上、必要な間口と階高がある場合に使用する。
  開口の配置と連続性を維持。空きが未確認の壁は窓手すりを継続する。
- `prepare_facade_life.py` が元の全建物の平面形、道路、水面から張り出しを検査する。
  同じ建物の凹部も障害として扱う。床や壁本体を変形・削除しない。深い部品は1.12m、短い庇は0.66mの検証済み空間に収める。
- 住宅は小さな玄関庇とインターホン、集合住宅・オフィスは入口の囲いと広い庇を持つ。
  店舗併用・商業用途の地上階には開口、短い庇、共有看板を配置する。
  看板は一つのアトラスで「喫茶・日用品・食料品・工房」を描く。実在の店舗や原画の文字を復元したものではない。
- 道路まで8m以内、経路に他の建物や水面がなく、元DEMの横断・縦断高低差が4cm以内の入口だけ舗装を加える。
  底を地面へ埋め、上面は元地盤最大値の35mm上。既存の地表仕上げ（DEM +16mm）より高くし、途中が埋没しないようにする。元の地形・道路の当たり判定を維持する。
  斜面に板や階段を仮定しない。入口の敷居はこの舗装面に合わせる。

## 夜とLOD

- 既存の昼夜・天候のdaylight値を共通マテリアルへ渡す。窓ごとのPointLightは作らない。
- 住宅・共同住宅・宿泊は住戸の識別子から色温度相当の3色と点灯状態を決める。
  隣接する対の窓は同じ住戸。色の選択と在室を別の決定的な値にし、同じ部屋がLODや読み直しで変わらない。
- 業務施設は昼光色で統一し、階単位で消灯。店舗は暖かな光、共用玄関は弱い光を使う。
  発光はガラス面だけへ適用し、枠・中桟・ベランダを光らせない。看板の発光は印刷面の明暗も保持する。
- 窓の中景は従来の2三角形パネル。ベランダは輪郭を残し、インターホン・小照明・入口舗装は近景のみ。
  元建物に基づくLOD距離は維持し、張り出しは描画の外接範囲にだけ加える。
  テクスチャ・マテリアルやBlenderファイルを一棟ごとに増やさない。

## 当たり判定

ベランダの描画と同じBlender部品に4個の単純な箱を記録する（床・前面手すり・左右袖壁）。
細い手すりの隙間は一枚の接触面として扱う。近傍60m、最大512箱を200msごとに選別する。
変化がなければ衝突用索引を再構築せず、部品の同一性を維持する。
タイルの破棄・再読み込み・ワールド切替時は対応する当たり判定も破棄する。

この構成の採否は、実際にベランダを含む場所で選別と索引の処理時間を計測して判断する。
実装は `facade-contacts.js`、`MetroCollision.setDecorations`、`MetroCity.update`。

## データ・検証経路

作業領域は `/Volumes/BLAZE/Spinward/inland-b-20260924/street-life-20260925/`。
kit原本は `izma-shared-facade-kit-v3.blend`、配信は `derived/facades-v3/kit.json`。
最終レシピは `derived/facades-v4/{east,central,west}.json` と各サブディレクトリ。
`facades-v3` は張り出し検査の中間生成物。元レシピと元の建物・地形メッシュは上書きしない。

ビルド選択は `VITE_METRO_FACADE_KIT=/facades-v3/kit.json`、
`VITE_METRO_FACADE_CATALOG=/facades-v4`。finish・lowrise・roadsは前段を継続する。

QAは既存の外観四街区・近中景・WebXR検査に、`metro-street-life.xr.mjs` の昼夜と店舗近景を追加。
店舗観察点は `fixtures/metro-street-life-views.json`。道路内包0.6m、他建物・水面から0.8m、壁への遮蔽物のない視線を元データで確認した点。
`playwright-webxr 0.3.0` はエミュレーションであり、実機HMDとは分けて報告する。

今回の目視で発見した回帰項目は、戸建ての玄関から道路まで通路が連続して見えること、
看板の日本語・英語が昼夜とも縦に潰れず読めること、庇が下側の文字を隠さないこと。
看板は8:1の横長アトラスを共有し、狭い間口でも文字の縦横比を保持する。庇がある場合は看板をその前縁に置く。

- 三帯各3,400サイト、計10,200サイトの別カタログを生成完了。元データの用途と壁の寸法から同じ規則を適用する。
  `derived/facades-v4/clearance-audit.json` のreadyを確認。壁・通路の集計はレシピ内の件数であり、固有建物数ではない。
- 関連Bun検査28件、Python検査2件、型チェック、production buildを通過。修正後は変更に関係する検査を再実行。
- 実GPU上のブラウザ検査17項目を通過：5地点の昼夜、夜VR、実プレイヤーのベランダ跳躍・着地、
  四街区の4方向、住宅2種の近中景、昼VRの移動、従来の歩行・跳躍・飛行、VR Placesで三帯間移動、VR高層壁面。
  `playwright-webxr 0.3.0`、左右眼64mm。実機HMDは未実施。
- 実プレイヤーは元地盤より高いベランダ床40.1497926712m上で静止し、跳躍後に同じ高さへ着地。
  設計形状の単体検査だけでなく、通常の移動物理で確認した。
- 戸建て通路の途中埋没、看板の文字比率と庇による遮蔽を目視で発見し修正。

## 範囲と限界

- 設計した意匠であり、各建物の現実のベランダ、店舗業種、在室、照明の復元ではない。
- 屋内・室内光の反射・地面への光の投射、ドアから入れる住戸、外階段は対象外。
- 平坦な入口だけを接続。斜面や複雑な敷地の経路は、地形に沿う設計が必要なため追加していない。
- ベランダと庇の非干渉は平面形に対する保守的な検査。上下の空間を使う特殊な張り出しは採用しない。
- 足元・飛行の既存物理を保持し、ベランダの接触だけを追加。接触の細部は低い費用で近似する。
