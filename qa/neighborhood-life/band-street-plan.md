# 居住帯全域の道路計画を旧格子から独立させる

tomingの再度の指摘「方眼を歪めた街路にしかならなくない？」を受け、長方形の
置換地区を追加する方式から、約39.84km × 3.15kmの居住帯全域の配置生成へ移った。
今回は**道路中心線の計画と比較図まで**。現行3D、建物、河川の地形、交通、案内へ
適用した段階ではない。川周辺だけを切り抜く未完の試作は実行経路から外した。

## 生成の入力と順序

`bandLand.ts` が、物理的な帯の寸法、川・護岸と緑地・施設の保留地、15か所の
地区中心、渡河候補4地点を先に与える。既存の橋から保持するのは中心位置
（接線564.2447m、軸1445.8065m）で、橋幅や地形全体の移植ではない。
追加の川筋、3つの橋候補、施設名・用途・中心位置は独自の仮配置。作品の全域地図を
復元したものでも、現存するPlacesや施設を同定・移動したものでもない。

`bandStreetPlan.ts` はCityRoad、旧道路の行列、境界出口、建物数、Three.jsを
入力・依存に持たない。土地座標と用途に基づき、次の順序で接続を決める。

1. 保留地の境界を回り、指定された候補地点でだけ渡河できる経路を求める。
2. 地区中心間の経路距離で接続木を作る。近い地区間に大きな迂回が生じる場合は
   接続を補う。河川の向こうへ一直線に道を描いてから橋扱いすることはしない。
3. 用途・需要の重みと地区の広がりから、間隔を確保した360か所のアクセス需要を
   生成する。固定の行列や、同形の地区テンプレートを反復しない。
4. 需要地点から既存の道へ接続し、途中で道に出会ったらそこで合流する。
   近接した需要地点間に2.1倍を超える迂回がある場合、上限内で接続を補う。
5. 全交差・途中合流を節点で分割し、重なる道路片を一本にする。

生成結果は575区間、接続成分1、独立閉路47。地区中心15か所と配置した需要地点の
孤立0、配置できなかった需要0。渡河は指定4地点だけ。近傍の接続追加44本を含む。
区間数は交差で分割後の値で、道路の名前の本数や描画負荷ではない。T字の数や閉路数
だけを街の良さの判定には使わず、実際の構成を全域図と詳細で見る。

既存橋の候補を一つ閉鎖すると、582区間、独立閉路46となり、他の3地点へ経路を
組み替えて全中心の接続を保持する。橋を移す小規模検査では中心同士を結ぶ組そのものが
変わる。全渡河候補を除いた検査では両岸を2成分として報告し、渡れない需要を明示する。
土地に需要地点を配置しきれない場合も `unallocatedDemand` に残し、ゼロ件を成功扱いしない。

## 参照と採用範囲

確定manifestから次の元画像を開き、SHA256を照合した。新着走査は実施していない。

- 第1話0006：`e4f0ea23acbadfb815e487d4438223948a9613b89d87871595fdb0826a6c7ea4`。
  近景の異なる高さ・窓形式の建築、低層屋根と頭上の連続した市街を観察。
  地区の違いを全域で考える背景に使用。中心位置・用途境界・個々の道路接続は
  読み取っておらず、今回の独自配置を原画から得た事実にはしない。
- 第4話0024：`74330871397a3b589db285d9d85f3c3e8323ff19547b5929454a827d67df056c`。
  アーチ橋と上部街路、低い護岸歩行帯、欄干、水面、周辺の建築・樹木を観察。
  川と渡河位置が接続を制約する入力分離へ採用。全域の川筋・橋の数や位置は
  このカットから同定できない。キャラクター・白い光の筋・霞の原因や演出色は採用しない。

元画像を編集・削除・成果物へ同梱していない。観察を計画の入力へ一部反映した段階で、
参照画像全体の消化や、描画への反映完了には数えない。

## 比較図

`qa/neighborhood-life/band-plan.ts` で、現行版の道路データと新案を同じ座標範囲へ描く。
新案の橋閉鎖、幹線のみ／集散道路込み、表示位置と表示幅を切り替えられる。
太さは識別用で、線は中心線。住宅路地・建物をまだ埋めていないため、道路本数や
空白の直接比較を完成度・密度の改善と解釈しない。

```sh
OUTPUT_DIR=/absolute/path/to/evidence bun qa/neighborhood-life/band-plan.ts
bun qa/neighborhood-life/band-plan-audit.ts
```

ブラウザで操作と表示を確認。左右詳細のviewBoxは同一、各566×440 CSS px。
独立画像レビューで土地の比較、旧格子と異なる構成、橋閉鎖の変化を確認した。
指摘を受け、全域図に詳細の範囲枠、左右に1kmの縮尺、地区名の背景、操作が新案に
作用する旨を追加し、独立再レビューでも改善を確認した。

全域図の薄い集散道路、鋭角分岐、長い行き止まり、用途が未設定の空白は残る。
現行図の縮尺バーと道路線が交差する箇所もある。図の読みやすさの検査は、正確な
通行判定や実際の都市らしさ、実機VRの保証ではない。

## 計算・通常画面・VRの検証

- `bun test`：991成功・0失敗、167ファイル、167.22秒。TypeScriptとproduction build成功。

  991.8〜1157.4ms。基礎のplanCity、建物・描画・フレーム時間は含まない。
  生成器は実行アプリにimportされておらず、今の起動・毎フレームには加算されない。

## 次に解く範囲

この帯全域の骨格を使い、鋭い合流・短い区間を整理して、交差点と道幅が収まる土地を
確保する。次に既存の生活拠点を名指しの保護・接続条件へ加え、地区内の細街路、
街区・敷地・建物と密度を生成する。元の格子の全出口を境界条件に戻さない。

橋の高さ、岸の連続地形、路面の曲率・歩道、建物入口、自動車の分岐・合流、
徒歩／運転案内、近遠景とLOD予算を同じ計画へ接続することが3D切替の条件。
現行の旧市街・室内・川沿い・座る等の生活体験を消して置換完了としない。
残る2居住帯の全域計画と、全3帯のシミュレーション切替も未実装。
