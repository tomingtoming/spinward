# 全18地区のIC模型

18地区の旧T字接続を、本線下の一般道と地区ごとに4本の出入りランプへ置き換えた。
**河岸接続を含めて正規データへ導入済み、通常5192で閲覧可能**。JCT9か所・高速道路の帯間連絡は別途未完。
2026-09-21のJCT候補は[別記録](colony-junctions.md)へ。まだ正規データへ導入していない。

証拠は `qa/webxr/evidence/colony-motorway-20260920/`。

## 最新の河岸接続（統合v8・source-v7・regional-v5）

既存の河岸試作の橋端（98, -80、高さ8.2m）から、建物間を抜けて外側の幹線へ合流する
約541mの道路をBlenderで追加した。最大縦断勾配4.08%。現物の橋・幹線路面を高さの
基準に使い、地形上のガイド曲線とは区別する。既存の幹線と住宅への接道を保持し、
合流部の歩道と柵だけを開けた。道路下へ突き出した地形105三角形を切り抜き、
範囲外の地形は原形を残す。

- 全経路の描画・衝突照合227,177点で不一致・予算超過0。最大描画差1.70cm、
  近傍最大27形状・2,614三角形。旧河岸接続の高さ不一致は解消。
- 河岸の実際の試作・近隣建物を含む検査は、路面と移動方向を描画・衝突それぞれ
  1,200点ずつ測定して不合格0。描画と衝突の最大差2.47mm。横断勾配を中心線高と
  同一視せず、中央は計画高、側方は実際の描画と衝突を照合する。
- 3帯のIC6経路と新河岸2経路をplaywright-webxr 0.3.0で歩行。
  `xr-v5`は7件成功し、夜間1件が歩行終了後の保存でENOSPC失敗。
  容量を戻し、同じ固定ビルドの`xr-v6`でその1件も成功。実機Questの測定ではない。
- 独立目視6枚で、橋と合流の可視範囲の路面連続性、柵の開口、両眼の形状一致を確認。
  Workbenchの密な斜め縞は実描画では見えない。路肩の細い緑帯、舗装の質感差、
  資料に比べた市街密度の不足は残る。
- 旧T字前提の検査を、保存済みの方向付きグラフ162プロファイルと72ランプに合わせた。
  6地区相互の到達性、節点と端点、勾配、ランプ入口・出口の柵の開口を検査する。
  交通シミュレーションへの導入とJCTの完成を意味しない。
- 関連単体30件と地面の遅延読込回帰16件が成功。1μmの境界余白を加える際に遅延
  mesh getterを範囲判定前に読んでしまった不具合は、値を読まないproperty存在判定に修正。
- 候補build・型検査成功。標準buildはpublic複製中に容量不足となったため、その未完成
  出力だけを削除し、固定候補と同じruntimeを指定した`bun run build --config ...`が成功。
  publicは固定プレビューへ原本と同一内容でhardlink済み。主要JS3本の一致も確認。

証拠は`river-progress-v4.json`、`river-visual-v4.json`、`preview-v4.json`。
修正後の全単体は`bun --smol test`で1,206件成功、0失敗（211ファイル、1,477秒）。
UI・読込復帰・ワールド切替の回帰7件も`xr-regression-v4`で成功した。
正規データへ導入後、実ソースからのbuildが検証候補とHTML・主要JS3本まで一致し、
通常5192へ切り替えてHTTP配信も照合済み。証拠は`canonical-motorway-installed.json`、
`canonical-build-equality.json`、`preview-canonical.json`。
導入時に置換前のヘッダーを`src/worlds/generated/izmaColonyBeforeMotorway.json`へ残した。
後から同じ模型を書き出す際は、`export_izma_motorway.py`の`--source-header`にその絶対パスを
指定する。置換済みデータへ旧三角形の削除位置を再適用しない。

## 照明追加までの経緯（模型v7・統合v6）

夜の合流路が暗いという目視検査の不合格に対応し、18 ICと3本の長手本線へ
支柱・腕・灯具を持つ照明7,258基を追加した。IC付近だけに配置した中間版では
模型境界の先が再び暗くなったため、本線全長で20mの共通配置間隔を使う。
他の道路との交差部と既存JCTでは支柱の干渉を避ける。点光源は既存の最大6灯の
近傍選択を使い、全灯を同時に動的描画する変更ではない。

保存模型と配信データの照合は7,258基すべて成功。支柱足元と実際の路面との差は
最大1.30cm、光源座標の変換誤差は0。照明を含む統合・保存検査も成功した。
最新候補のVR歩行6件は `xr-v4/`、UI・読込・ワールド切替の回帰7件は
`xr-regression-v2/` ですべて成功。型検査・候補buildも成功。
最新5画像と旧夜景2画像の独立比較で、夜の近中景の路面・道路端の改善、灯具と支柱の
接続、可視範囲での通路確保を確認。中央線上の浮遊光や片眼の欠落は見つからなかった。
照明間・遠方の暗部は判定保留で、合流先の既存本線では白線が確認できない。
白線不足は路面の明るさと別の残作業。歩道端の台座の有効幅も静止画では判定しない。
実機Questの性能は未測定。

全経路の検査で、遠方の道路タイル境界を両側の範囲判定が9.09e-13mだけ除外する
不具合も再現した。三角形を持つ地面の候補選択へ1μmだけ余白を追加し、三角形への
接地判定は変更しない。実座標の再現テストは修正前に失敗、修正後に成功。
関連単体検査65件が成功し、この原因による高速道路の取りこぼし114点は解消した。

交通経路は162縦断プロファイルと、138節点・186区間の方向付きグラフを候補として
作成。左側通行の流入36・流出36と、各帯の6地区間の到達性を検査した。ただし
**経路全体の実景との照合は未合格で、交通機能への導入はしていない**。
実際の河岸試作地区を含む227,034点の描画・衝突検査では、旧 `a-river-access`
だけに高さ不一致290点、近傍形状数超過26点が残る。旧計画の始点高3.286mに対し
現地の床は8.293m。建物を横切る古い直線を残して高さだけ合わせず、既存の橋・街路と
外側の幹線を結ぶ接続を造形する必要がある。他区間の高さ一致は交通の通行保証ではない。

## 初期候補で見つかった問題

`survey_izma_motorway.py` は18地区×6候補を比較する。既存の建物・入口・公共空間等
19,112形状に対し、選んだ全18候補の2D投影重複は0。既存幹線の斜行に合わせて
ランプの分岐点を置き、実際に共通道路上へ接続することを検査した。
これは用地検査であり、他路線・基礎・水系を含む3D干渉検証の代わりではない。

`plan_izma_motorway.py` はBlenderのBVHで現在の地形を参照し、共通道路と
72本のランプの高さを解く。本線の高さ、元の一般道との接続位置、ランプ末尾120mの
合流高は固定。縦断勾配は最大6%。18地区すべてで計画制約を満たし、計画上の
一般道から本線桁下までは最小15.294m。法令・設計基準や耐荷重の認証ではない。

`build_izma_motorway.py` は、展開座標と円筒座標の2シーンを保存する。
最初の候補は108メッシュ・67,403頂点、地形へ下ろした693本の支持脚を含む。
原本や配信中のシーンを上書きせず、候補の各オブジェクトに `runtime_accepted=false`
を記す。原本の古いT字交差点はまだ残っている。

3帯の代表地点 a-port / b-housing / c-forest の俯瞰と下抜け計6画像を独立確認。
長手本線の両側の曲線路と下抜けは見える一方、接続部に突出した縁・細片を確認した。
第2候補では同じ高さの路面の重複を切り抜き、隣接路内の側壁と歩道を取り除いた。
第2候補は108メッシュ・66,086頂点。同じ6視点の独立比較で突出縁の改善を確認し、
大きな新規欠落・橋下閉塞は見つからなかった。

ただし保存済み路面へ56,082地点からrayを当てると、接続付近の197測定で計画高との
差が5cmを超え、最大0.665mだった（同一地点の展開・円筒の両測定を含む）。
床の欠落は検出されず、579測定の本線桁下高さは最小15.384m。
**第2候補は数値検査不合格**。各ランプの中心点だけを一般道へ合わせても、幅を持つ
接続面の高さは一致しない。切抜きで見た目の縁を除くだけでは解決せず、接続部分で
共有する路面の高さとランプへの遷移を設計する必要がある。
`candidate-v2/assets/blender/izma-motorway-audit.json` に全失敗位置を記録した。

地形へ埋まって見える暗帯の仮説も調べた。第1候補の計画点28,311点を実際の地形に
照合すると、展開座標で最小0.162m、円筒座標で最小0.159mだけ地形より上にあった。
画像の広い暗帯は影と整合するため、地形が道路を覆う欠陥として変更しない。
この検査は計画点の高さと地形の比較。保存した道路面自体の検査とは分ける。

導入後には全域回帰とplaywright-webxr 0.3.0の実際の移動を確認する。
模型の作成をICの完成と数えない。
