# 用途と地区を保つ対岸の夜景

## 問題と変更

建物を共通Blender構造へ置き換えた後、遠景のshell emissive bakeは全建物で `#ffd89b`、alpha 0.12へ上書きしていた。既存の地区の明暗・建物別の変動を計算しても採用せず、乱数で消灯側になった建物も同じ値だった。住宅・オフィスの区別がある近景と、遠方で形状を省略した場所の照明が揃っていなかった。

生成建物には近景と同じ `colonyBuildingDesign` を使う。窓の面積、既存の点灯率、低層部の用途を平均した光を、既存の `nightDistrictGain` と `nightSpeckle` で調整する。住宅の部屋別の色温度は従来のまま、サブピクセルの平均色をGLSLとbakeの共有定数から取得。オフィス・商業の上階は昼光色、住宅は混合色、商業階を持つ場合だけ床高の割合に応じて暖色を混ぜる。遠景代理面の露出換算には上限0.30を持たせ、部屋の光量や実光源は増やさない。

建物の構造ボリュームごとの描画を保ち、中庭を敷地全体の光で埋め戻さない。少数の手作業のpilot GLBは従来の暖色値を維持。道路のcore/halo、昼のalbedo、街路・建物配置、窓の個別点灯・コリジョン・LODは変更していない。追加の描画パス・ライト・テクスチャ・Blenderモデルもない。設計値は一棟ずつ求め、全市分の追加デザイン辞書は保持しない。

これは遠景代理テクスチャの改善で、各室の照度の物理積分ではない。近景の室内灯と同じ用途・点灯率・平均色を用いるが、全方向の放射輝度の厳密一致は主張しない。元資料の不規則な道路網や密度の全面再現、雲・色付きの霞は今回の対象外。

## 再実行と判定線

```sh
bun test
bun run build
SPINWARD_URL=https://127.0.0.1:5192/ LABEL=reviewed node qa/neighborhood-life/night-districts.mjs
SPINWARD_URL=https://127.0.0.1:5192/ TIER=quest LABEL=reviewed node qa/neighborhood-life/night-districts.mjs
SPINWARD_URL=https://127.0.0.1:5192/ bun run test:xr
```

URLは所有確認済みproduction previewへ置き換え、検査中のアプリビルドを固定する。`LABEL=before` は変更前ビルドでのみ取得する。比較には同じtierのbefore JSONが必要。

- unit: 住宅・オフィスの平均色、窓面積・点灯率、同じ建物に対する地区の核／空白、再生成の決定性、実bakeへ渡る色とalphaの多様性。道路値とpilotの暖色を維持。
- browser: 対岸・副中心・外側地区・昼・街路の5視点。視点・時刻が変わっても都市配置と両テクスチャの内容hashが一定。before/afterで都市配置と昼のbakeが一致し、夜のbakeだけ変わる。昼の頂点で夜発光がほぼ0。GPU・ページ例外・shader errorを記録。
- XR: 実際のMenuから入場し、地区の中心が画面内にあることを確認。0/±25°の両眼で実テクスチャ・UV距離範囲・都市行列が不変、撮影と終了が同じセッション。全suiteで手首・コントローラ・退出再入場も通す。
- visual: before/afterで対岸の灯りに暖冷・明暗があり、床全体の均一発光や明白な穴を新設しない。既存の道路・塔・建物輪郭・窓・昼景・近景UIを保持。両眼で同じ夜景が見え、片眼だけの消失や逆ロールがない。正確な照度や実機Questの可読性・性能は画像から保証しない。

最初のブラウザ検査は時刻0.42を完全な昼と誤って扱い、消灯判定で止まった。既存の昼光は余弦曲線で0.5が頂点であるため、昼の比較条件を0.5に揃えて撮り直した。ランタイムの昼夜曲線は変更していない。
