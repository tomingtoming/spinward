# 複数街区をつなぐ曲線道路と沿道建物

全市移行の第6段。共通の道路グラフを使い、3居住帯それぞれで約900×1,285m、
4×4の連続街区を置き換える。合計48街区、18本の曲がる通過道路、境界を含む
63交差点。全市の道路網を置き換え終えた段階ではない。

## 配置と生活動線

道路の位置は建物予算に依存しない。幹線と生活道路に異なる緩い曲線・斜行を与え、
地区の外周では従来の道路と位置・接線を一致させる。旧道路面を地区境界で切り、
新旧の線を重ねて二重の道路にしない。3居住帯それぞれの接続は維持する。

道路沿いに幅・奥行き・高さ・色調を変えた区画を作り、建物を沿道の向きへ回転。
車道への侵入、既存建物との干渉、入口までの通路を共通の接道認証で検査する。
既存のBlender建物・バルコニー・屋上設備・LOD・近距離コリジョンを再利用する。
16,000／18,000／64,000棟のどの設定も、置換前後の建物総数は同じ。

車は地区外から同じ車両・車線のまま入り、曲線に沿って走り、信号の停止位置を
参照する。無信号の交差点では道路種別と既存の通過交通を使って優先権を決める。
通過車両がいる間は脇道で待ち、空くと再発進。任意の右左折を選ぶ都市交通ではない。

住民は曲線歩道の安全な区間を往復する。車道を横切る区間は生成しない。
既存の近隣人数上限（desktop 8人、Quest／phone 4人）と描画バッチを共有し、
都市全体に歩行者経路を展開しない。徒歩・運転案内も同じ道路を使い、地区境界の
旧集散道路を渡る場合も実際の横断歩道を通す。

街灯は曲線に沿う実距離で並べ、歩道上の柱から車道へ腕を伸ばす。灯器512枠と
実ライト数の上限を維持する。遠景の昼夜テクスチャにも同じ曲線と回転した屋根を
描き、近景と別の旧格子が残らないようにした。

## 試行で直した点

- 初回の車両確認では、新しい経路が車両割当の後ろに入り、定員までに選ばれず
  新道路上の車が0台だった。近隣候補の中で新旧を貫く経路を先に割り当て、
  実際に地区の範囲内を走る車両座標をQAの必須条件にした。
- 独立画像レビューで、斜めから見る歩道端に草色の帯を検出。上面だけの舗装の
  下を見通していたことをレイキャストで確認し、地面まで届く縁石側面を追加した。
- 夜景レビューで曲線区間の街灯の欠落を検出し、柱・腕・灯面を曲線へ接続した。
  切断した旧道路の中心位置が変わっても交差点からの離隔を保つよう、街灯の
  軸方向座標も修正した。
- 境界の横断歩道を徒歩案内へ含め、生活道路の歩道が幹線の通行禁止帯を
  上書きしないようにした。経路の圧縮点だけを数える初回の回帰検査は失敗した。
  折れ線の区間内も補間して、実際の横断歩道内を通ることを検査する。
- 初回の費用測定で、住民の近隣経路の再生成に約19〜20msを検出した。
  0.75秒ごとに再実行する費用を避けるため、近隣の64m区間だけをキャッシュする。
  範囲外へ出た経路を破棄し、道路グラフが変われば再生成する。

## 参照の扱い

資料追加の走査は行っていない。固定manifestの第1話0004・0005、第4話0024を
再確認した。住宅の窓・屋上、橋とその上下の生活動線は観察できるが、この数枚から
都市全域の道路形状は決められない。今回の道路配置は本人の非直角化の指示を受けた
Spinward独自の設計で、イズマの街路図を復元したという主張ではない。
機体・戦闘・人物や作品固有の看板を複製していない。manifestの実装状態は維持した。

## 検証入口

```sh
bun test
bun run build
bun qa/neighborhood-life/native-districts-audit.ts
SPINWARD_URL=<preview> LABEL=final node qa/neighborhood-life/native-districts.mjs
SPINWARD_URL=<preview> bun run test:xr
```

変更前JSを `BASELINE_JS` へ渡すと、同一の9視点で変更前を撮影できる。
`native-district-views.mjs` に3帯の俯瞰、幹線歩道、交差点、入口、夜、境界の位置を固定。
ハードウェアGPUを必須とし、ブラウザ例外・WebGLエラー、新地区、実車両、実住民と
人数上限を読み取り専用のプローブで検査する。

VRは実際のMenu入場、左右眼、手首Placesへのコントローラ操作、頭部ロール0/±25度、
スティック歩行、車と住民の移動、セッションを指定した終了を検査する。
既存の上階住戸、川沿い、Garden、身体への車両の譲り、UIの回帰も一緒に実行する。

## 残件

- 配置変更は各帯の約1.16km²に限る。外側の大部分は従来の格子。
  新地区も4×4の接続関係を引き継いでおり、T字・不整形街区・地区ごとの道路密度は次段。
- 軽量設定では広い緑地に建物が離れて立つ。密集した連続市街地になったとはしない。
- 新しい回転建物の一般室内・内階段は未接続。軸に固定された旧室内は新地区には
  作らず、既存のニャアンの部屋など別地区の室内を維持する。植木鉢・前庭・路肩駐車も残件。
- 交差部で旧路面テクスチャの車線破線・中央線が横断歩道や停止線を横切る点は
  前段から残る。全交差点の塗装が完成したという判定にはしない。
- 実機Questの速度・装着感、連続動作でのちらつき、全車両の渋滞解消は未検証。
  CPU生成時間、メッシュ数、Chromeでのエミュレーションを実機FPSへ読み替えない。

次はT字路と不整形街区を含む接続構成へ進み、地区外へ移行範囲を広げる。
小物・窓色・この地区の密度調整だけへ固定しない。

## 最終の計算検査と費用

Bun 1.3.10で965件成功、0件失敗。TypeScriptとproduction build成功。
新規10件は3予算の配置・接道・建物干渉、正逆方向の車両の継ぎ目と停止位置、
徒歩／運転案内、境界の横断、無信号の譲り、歩行経路の安全性とキャッシュの破棄、
街灯の車道侵入と切断道路での離隔、歩道側面の遮蔽を含む。

最終監査は全予算で3接続成分・63交差点、参照先のない入口0、欠けた横断方向0、
未制御の幹線交差点0。新しい街灯の候補は319地点。遠距離まで319灯を同時描画する
という意味ではなく、従来の距離選択と512枠の予算で配置する。

これらは新地区内の同時走行台数ではない。代表の幹線歩道では住民4人／6人が表示され、
それぞれの人数上限以内だった。
