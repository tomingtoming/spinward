# 全域道路の合流整理と幅付きの路面

後続の [川と道路の高さ](band-elevation.md) で、北部の残る鋭角を解消し、
河川・橋・高架の独立した立体化検討へ進んだ。以下はその前段の検証記録。

前段の専用道路予約を含む全域案を `prepareBandStreetGeometry` に渡し、近接する
交差点と接近路を整理してから既存の `StreetPath` / `StreetSurfacePlan` へ変換する。
道路生成器の入力を旧格子へ戻さず、一本の居住帯全域で処理する。
**現在の居住中アプリへは未適用**。中心線計画から路面・歩道・円筒メッシュへ進んだ
検討段階で、走行可能な一般道や高速道路が完成したという意味ではない。

## 何を整理するか

`refineBandRoads` は20m未満で隣接する分岐点を統合し、30°未満の合流では
一方の接近路を相手の道へ投影して、それ以降を共用する。道幅と歩道を足した
範囲に入る外側の接続点は、固定点でなければ付属する道路ごと共用道へ寄せる。
保留地内を切る提案、固定点の消失、接続成分数の変化、従来90m以内の開いた経路で
到達できた需要地点の喪失、新たな鋭角・短接続の増加は受け入れない。
問題数が同じ場合は道路区間が減る提案だけを受け入れ、反復回数にも上限を置く。

地区中心、ICの一般道ゲート、使用中の渡河・立体横断端点は移動しない。
橋・立体横断そのものの区間と属性も保持する。固定点同士が近すぎるなどの
解決できない入力は診断に残し、基準を満たしたことにはしない。

| --- | ---: | ---: |
| 30°未満の合流 | 8 | 1 |
| 20m未満の分岐点間の接続 | 6 | 0 |
| 分割後の中心線区間 | 633 | 625 |
| 一般道総延長 | 195.210 km | 193.384 km |
| 接続成分 | 1 | 1 |
| 独立閉路 | 48 | 46 |
| 車道メッシュの三角形 | 14,779 | 14,997 |
| 歩道メッシュの三角形 | 16,724 | 17,015 |

統合・共用の編集は14回。三角形数は同じ円筒面変換で比較した一般道路面だけの値で、
建物、縁石の側面、高速道路、描画呼出し数や実機FPSを含まない。
短い形状サンプル全部を消したわけではない。予約地の曲線に沿う次数2のサンプルや
固定された中心に終わる区間は別であり、最短サンプルは0.639mから2.121mとなる。

幅は既存の `getStreetProfile` を使い、幹線の車道19.5m・片側歩道3m、集散道路は
車道12m・片側歩道2.5m。重なりは既存の路面所有・歩道切抜き処理へ渡す。
`buildStreetSurfaceGeometry` で半径3,200mの円筒に沿わせるところまで共通化した。
独立画像レビューで見つけた次数2の曲がり角のV字欠けは、端点の縁同士を面取りで
つないだ。同じ高さ・階層の端点が二つだけ合う箇所に限定し、路面と歩道双方の
所有・切抜き処理へ渡す。`StreetSurfacePlan` の `joinEnds` を明示した場合だけ
有効となり、今回の全域案で使用する。既存アプリの配置は従来の既定値を保つ。
三角形合計は31,503→32,012、約1.6%増。角丸・車線幅の移行を設計したものではない。

一般道の平面検討なので全体を同じ仮の高さに置く。橋の縦断・桁下高を設計した
結果でも、専用道路を一般道のグラフへ混ぜた結果でもない。

## 再現と検証

```sh
OUTPUT_DIR=/absolute/path/to/evidence bun qa/neighborhood-life/band-street-geometry.ts
```

`map.html`、`viewer.js`、`summary.json`、`plan.json` を作る。HTMLの図は実幅の
多角形、3D比較は上記の実メッシュ。同じ場所・同じカメラの整理前後を表示し、
南端IC、東岸、短い交差点間、北部の未解決箇所を選択できる。中心線の表示切替、
3Dの真上／斜めと背景明暗も操作できる。暗背景は夜景の照明検査ではない。
比較画面はApple M1 Pro / ANGLE Metalを確認し、software rendererを拒否する。
最終の2D証跡は1280×720、左右各583×480 CSS px、同じviewBox。凡例を含む
`*-final.png`を使う。fullPage撮影の崩れた記録は採用せずevidence-indexで除外した。
独立した画像レビューで面取り後の外縁を明暗両方で再確認し、欠けの解消と、
その周囲に新たな隙間・突出が見えないことを確認した。
最終の計画整理＋路面生成は一回の計測で約2902ms。複数回の速度分布や実機負荷の測定ではない。

追加7テストで、小さな対照地形と全域案の両方を検査した。固定点・指定横断・
保留地・需要地点を保持し、既存 `StreetNetwork` でも同じ接続成分・閉路となる。
有限幅の車道間、車道と歩道の重複面積は1e-5 m²未満。円筒面の頂点の半径誤差は
1mm未満。これは道幅の接続・角丸・車両旋回・歩行可能性をすべて保証する検査ではない。

角の補修を含む最終コードの全 `bun test` は1,007件成功・0失敗、188.21秒。
TypeScript・production buildも成功。既存の大きいchunk警告のみ残る。生成時間は別途記録する計画時のCPU費用で、
実行アプリのフレーム時間に加えた費用ではない。

証跡は `qa/webxr/evidence/band-street-geometry-20260914/`。VR検証の対象は
配置を変更していない既存コロニーで、幅付きの新案をVRへ適用した検査とは分ける。

playwright-webxr **0.3.0** の最終ビルド検証は2件成功（約1.1分）。実際のdesktop-menuと
Quest型entryから入場し、Places・案内・雨切替・Controlsをコントローラで操作、
左右眼・頭部roll、UIの入力占有、終了・再入場と古いsession IDの拒否まで確認した。
Chrome 152 / Apple M1 Pro / ANGLE Metal。4セッション・4終了のエミュレーションで、
物理Questの測定ではない。単体検査とは順に実行し、配信buildを固定した。
最終配信は `index-BqABab2P.js`、SHA256 `e38d2bff868d26dd066e8510090369537c941421f36cbc60b0a77522d0548fd7`。
証跡は `xr-final/`・`xr-final.log`・`build-final-proof.json`。
Controlsと頭部rollの左右眼画像も独立レビューし、片眼だけの主要表示の欠落は
見つからなかった。小さい補足文の全字判読や実機視認性は保証しない。

## 全市移行の残件

北部の並走路では、元の0.466°の問題が約385m先の接続へ移り、0.855°の鋭角が
残る。改善済みには数えない。長い接近路を区間単位で共用する処理と、接道需要の
保護を一緒に扱う必要がある。現在の貪欲な局所整理は道路網の最適解を保証しない。

次は幅を持つ路面の外周・交差点の角・歩道の連続、実際の川と橋の高さ、IC/JCTの
曲率・勾配・上下線離隔・支持構造を解く。既存生活拠点を保護条件として加え、
街区・敷地・建物・入口・交通・徒歩と運転の案内・近遠景へ同じ最終道路を渡す。
南端ICの幹線から集散道路への急な幅の変化、T字路外縁の小さな段差も残件。
従来の `plan.accessLinks` は整理前の距離であり、この後段の経路案内へ流用しない。
全市の既存配置への切替、他の2居住帯への展開、実機Quest性能は未検証。
