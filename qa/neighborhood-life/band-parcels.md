# 一居住帯の街区・敷地と生活拠点の保護

全長39.84kmの居住帯へ、川・施設・専用道路・既存3拠点を先に確保する敷地生成を追加。
一つの連続した土地から69街区と10,111の沿道区画候補を作る。長方形の置換地区を
並べる方式へ戻さない。**全域案のオフライン生成で、現行コロニーへの適用ではない。**
候補数は描画する建物数や完成した住宅地の数ではなく、用途・密度・高さは未決定。

## 参照と判断

確定manifestの `izma-ep05-0039` を1920×1080で再閲覧し、SHA256
`f12cea4b1e98d69771eacac21cfcf3a84240aae1ec5c241bf08230ddffd96088` を原本と照合。
大小の建物、複雑な屋根・中庭状の空間、沿道の小棟、木と建物間の空きが見える。
敷地境界自体は読み取れず、見える道路には直角もある。この画像を非格子道路の
根拠や測量図とは扱わない。白い雲・煙状の遮蔽は原因不明として除外し、戦闘効果、
機体、人物、文字、作品固有の屋根形状を複製しない。原本は変更・同梱しない。
建つ土地と空いている土地を分ける考え方へ使用。既存の建物比率への採用と未反映事項は保持。

## 先に見つかった移行上の衝突

旧全域案の川の予約地には、実在するカフェとアパートの中心が入っていた。
カフェの展開座標は `(391.121, -300.943)`、その地点の旧川予約幅は
`x=256.277〜566.277`。アパートは `(286.310, -199.489)`、予約幅は
`x=265.161〜575.161`。現行世界で水没していたという意味ではない。

`bandLivingPlaces.ts` がBlender由来の3つの実際の建物契約JSONから、位置・寸法・
敷地・入口を読む。手書きの別座標へ移し替えない。建物と既存敷地の外へ20mの
計画用余裕を取り、最大の幹線車道・歩道が境界をかすめても元の敷地を侵さない。
入口側の保護域境界に道路の接続点を設け、arrival中心へ接続する。
20mはSpinwardの設計値で、法規や歩行安全の認定値ではない。

川筋案に `(650,-850)` と `(650,350)` の制御点を加え、カフェ・アパートを避けた。
既存橋のアンカー `(564.244685,1445.806452)` と全7IC・JCTの配置は保持。
新しい一般道は628区間、接続成分1、独立閉路46。30°未満の分岐・20m未満の
分岐間隔は0。3つの接続点は整理後も残り、到着中心へつながる。
入口から新道路までの横断、歩道への取り付け、裏口の接続はまだ認証していない。

## 敷地の生成

`bandParcels.ts` は専用道路の予約地を含む輸送計画を受け取る。凹形の川筋や
予約地は凸片へ三角形分割し、元の面積との一致を確認してから差し引く。
車道・歩道の実面も差し引くので、中心線の幅だけでは拾えない交差部の張り出しを避ける。
共有する辺で残土を連結し、三角形の内部境界を街区境界と見なさない。

既存の `streetParcels` の接道点・二等分線・奥行き制限・建物の収まり判定を使う。
最初の俯瞰検査で、疎らな道路端の区画が何百mも細長く伸びる問題を発見した。
全域案には間口上限40mを追加し、道沿いの区画が遠方の土地まで占有するのを止める。
この上限は任意指定で、現行の地区生成は従来の結果を維持する。
長い区画の失敗例と上限、旧既定の同一性をテストへ追加した。

| 対象 | 最終値 |
| --- | ---: |
| 居住帯全体 | 125.495km² |
| 予約地・道路等を除いた土地 | 100.964km² |
| 連結した街区 | 69 |
| 建物が収まる沿道区画候補 | 10,111 |
| 区画の所有面積 | 11.831km² |
| 未割当の土地 | 89.133km²（残った土地の88.3%） |
| 輸送計画と幅付き道路生成 | 約5.97秒 |
| 敷地生成 | 約4.86秒 |

間口制限前の区画所有は16.972km²、未割当83.2%。候補数を維持しながら余分な
約5.14km²を未割当へ戻した。時間はこのホストでの単発のオフライン生成値。
毎フレーム実行する処理ではなく、Questの実機描画性能を示さない。

## 検証と再現

```sh
OUTPUT_DIR=/absolute/path/to/evidence bun qa/neighborhood-life/band-parcels.ts
```

出力は `index.html`、`viewer.js`、`land.json`、`summary.json`。地域選択・間口の
色分け・建物候補の表示・拡大移動が可能。川と専用道路は**予約地の幅**を示し、
水面や桁の実幅ではない。図は平面であり、高さ・斜面・走行性の検証図ではない。
検証資料: `qa/webxr/evidence/band-parcels-20260914/`。

新規検査は、凹形予約地の湾を埋めないこと、全街区片と実車道・歩道・予約地の
非重複、全区画の間口・接道・建物の収まり、区画同士の二重所有なし、面積収支、
既存3拠点の建物・敷地と道路・他予約地の非重複、接続点の到達性を確認する。
厳密な重なりと数は画像判定に任せず計算で検査する。

- 最終 `bun test`：**1,029件成功、0件失敗、208.35秒**。初回は間口修正前に
  1,027成功・1時間切れ（210.73秒）。既存64,000棟の地区接続テストが10,129.89msで

  上限は変更しておらず、根本的な高速化や負荷依存の解消とは扱わない。

## 次に必要な移行

全域案は幹線・集散道路とその沿道まで。残る広い土地に生活道路と公共空間を置き、
用途と密度を決める必要がある。間口の細部だけを磨き続けず、既存の広場・公園・
川沿い・Garden street等の保護契約を広げ、実行世界の建物予算・LODと接続する。
まず3拠点の入口から歩道への徒歩接続を認証し、その後、車・住民・案内・コリジョンを
同じ新道路へ切り替える。全10,111候補をそのまま追加描画しない。
IC/JCTの車線・ゴア・柵・支柱、一般道との幅・高さの全体監査、橋の向きと
川沿いの上下移動、実機Quest性能は引き続き残件。
