# 地区単位の読み込み：データ・描画・衝突と身体移動

**身体移動へ接続し、全体検査を通して通常プレビューへ反映済み。**
基盤地形と固定地面9層を区域ごとに読み込み、正確な床がそろうまで物理と回転時計を
一緒に止める。これは全域を増築するための実行基盤であり、街の密度や帯間交通の
完成ではない。旧版との比較後、5192の配信物を検証済み候補へ更新した。
`landscape=authored` を指定する設計景観で有効。指定しない通常起動は従来の街を維持する。

## 身体移動への接続（2026-09-19）

- 起動時の参照を `izmaColonyRuntime.json` へ変更。遠景と目録を先に読み、近傍の正確な
  地面・衝突を区域ごとに取得する。元の `izmaColony.json` は制作と比較用に維持する。

  列挙するだけで、未取得の区域を参照しない。到着時に実際の床を解決する。

- 徒歩・運転・列車は次の1フレーム分の移動幅、自由飛行と投射物は慣性系での次の位置も

## 近傍データの分割

`assets/blender/colony_spatial_data.py`は、基盤地形と`fixed`を持つ全層を処理する。
現在は建築・公共空間・近隣街区・鉄道・土地利用・歩道・角地・街区置換を含む9層。
層の名前を別リストで維持しないため、新たな`fixed`層を追加しても黙って除外しない。

- 描画三角形は重心の512m区域に所属し、材質・頂点順・座標を保持する。
- 衝突面群は境界をまたいでも分割せず、安定した`層名:番号`で1区域へ所属する。
  目録の境界は三角形の全頂点を包み、所属する512mセルの外へ出た面も覆う。
- 数値の丸めや量子化をしない。整数と浮動小数点、符号付きゼロも保持する。
- 個々の取得データは2MiB以下。全区域のサイズを確認してから内容アドレス付きJSONを
  書き出す。既存ファイルの内容が違えば拒否し、原本や実行時indexを置き換えない。

45棟改訂の原本SHA-256は
`2f0a507e6b74e516d05eb50712c6c9b3e09088a4f494947627cbe32e5e6c7164`。
この原本全体からの実測は次のとおり。

| 項目 | 結果 |
| --- | ---: |
| 区域 | 1,887 |
| 地区データ合計 | 94,361,419 bytes |
| 最大の1取得 | 2,090,069 bytes |
| 目録 | 2,285,727 bytes |
| 描画三角形 | 1,392,885 |
| 衝突三角形／面群 | 1,352,708／16,588 |

全描画面の材質・頂点順・座標の多重集合、および各衝突群のID・面の順序・座標・境界・
接地フラグを原本と照合し、一致した。これは通信量の圧縮率や実機メモリの測定ではない。
初案では衝突の詳細な占有矩形も目録へ含めて41,027,635 bytesになったため除いた。
細かい占有範囲は区域が準備された後、既存の上限付き衝突キャッシュで求める構成とする。

小さな交差区域の例、将来の固定層、数値型・符号付きゼロ・面の向き、面群の非分割、
データ上限、決定的な再書き出し、破損済みファイルの拒否を4つのPython検査で確認した。
実行は`python3 -m unittest discover -s assets/blender -p test_colony_spatial_data.py`。

## 遠景の生成と形状の検査

`export_izma_spatial_data.py`は独立したBlenderから候補を別ディレクトリへ出す。
円筒上の実際の座標で簡略化し、残った頂点には元の展開座標をそのまま使う。
材質を保ち、連結した面ごとに採否を決める。衝突面は簡略化しない。

- 区域を共有する35,954頂点を保護し、その境界の辺も元と一致させる。
- 区域内部の輪郭は、元と候補が同じ折れ線へ各5mm以内で帰着することを調べる。
  そのため両輪郭の隔たりの上限は1cm。連続した削減で誤差が累積しないよう、
  途中で除いた全頂点も照合する。近景との区域境界へこの許容値を流用しない。
- 全三角形の頂点・辺の中点・重心を双方向で照合し、標本距離を10cm以下とする。
  重心で面の向きも照合する。これは連続面全体のHausdorff距離の証明ではない。
- 不合格の連結成分は原形を残す。最終候補では12,213成分をそのまま使用した。

| 項目 | 最終候補 |
| --- | ---: |
| 遠景の三角形 | 1,175,926（元1,392,885から約15.6%減） |
| 照合した点 | 7,001,710 |
| 採用面の最大標本距離 | 0.0998482m |
| 開始用JSONのpart合計 | 72,955,542 bytes／47 parts |
| 開始用index | 1,729,075 bytes |
| 遠景の独立blend | 29,775,268 bytes |

元の開始用part合計120,424,758 bytesに対し約39.4%減。圧縮前データの比較であり、
ブラウザの実通信量、起動時間、メモリ、Questの描画速度の測定ではない。
まだ約117万三角形・約73MBあり、十分に軽いと結論していない。

初期の`dissolve_limit`は点で接する非多様体の庭でクラッシュした。辺だけの統合は
輪郭の頂点を残し、64m幅への追加分割で元より増えたため不採用。円筒上で頂点も
簡略化する初案は約65%減ったが、輪郭が変形したためそのまま採用しなかった。
計測では数µmから約65cmの境界変化が混在したため、共有境界の明示的な保護と
上記の形状検査を導入した。旧`package/`、`package-curved/`等は不採用の証拠。
**候補として参照するのは`package-final/`だけ。**

曲がった輪郭・保護頂点・穴・逆向き面・盛り上がりの喪失を4件のBlender検査で確認。
3居住帯の原形／遠景／1区域だけ近景の9画像も生成した。これは固定地面だけの
比較で、建物・照明を含む街の評価や、実アプリでのLOD移動の検査ではない。

## 読み込み・描画・衝突の実装

`ColonyRegionStore`と`AuthoredColony`へ、streaming目録がある場合の描画経路を実装した。
以下は準備段階の実装契約。候補アプリへの接続状況は冒頭を参照。

- 必要な全区域がそろったときだけ準備済みになる。上限は取得3件同時、保持32区域、
  元JSON24MiB、数値4,194,304個、描画インデックス1,572,864個。
  JSON量・数値数・描画入力を別に制限し、JSヒープの実測値と混同しない。
- 個々の応答は2MiB以内で、バイト数とSHA-256と構造を検査する。
  衝突ID・面群数・境界・高さ・接地フラグも目録と一致させる。
- 再試行は5秒間隔・最大3回。離れた区域や破棄後の遅延応答は採用しない。
- 材質ごとの遠景の描画インデックスを区域単位で置換する。近景の準備後に遠景を隠し、
  解放時には遠景を戻してから近景のGPU幾何を破棄する。
- 衝突記述子は常駐目録から作り、解放・再取得でも同じ物体を使う。
  未準備の区域への衝突アクセスは明示的に失敗し、空の床として扱わない。
  詳細な占有範囲と展開した面は既存の128件／4MiBキャッシュへ置く。
- 元の衝突境界が頂点より多い小数桁を持つ箇所があるため、区域境界には両者の和を使う。
  頂点の丸めで準備範囲をわずかに狭めることも避ける。

破損・キャンセル・保持上限・遅延応答・再試行・近遠切り替え・再取得後の床を
14件の対象検査で確認した（既存の衝突キャッシュ検査6件を含む）。
実データの172訪問先では、各地点256m以内の必要区域を取得してから床を問い合わせ、
原本の全固定層による床の高さと一致した。最大6区域、最大5,460,162 bytes。
全区域の境界2点と中心の5,661地点でも、選択数・JSON量が設定上限以内だった。
これは全経路の移動検証や、高速移動・2地点同時保持の実測ではない。

## 接続前に設定した検査項目

以下は準備段階のチェックリスト。上記の候補版で接続し、未検証範囲は残している。

1. 訪問先の存在・座標の検索を床の問い合わせから分ける。現在のUIの利用可能地点列挙が
   未準備の地面を読まないようにする。
2. 到着先を準備してから身体を配置する。準備中も現在地が必要なら両地点を要求へ含める。
   徒歩・自由飛行の着地・鉄道の次の移動を先読みし、未準備なら物理と基準系の時刻を
   一緒に止める。頭の追跡・描画・UIは止めない。
3. 通信失敗と待機を利用者に伝え、世界切り替え後の到着要求を破棄する。
4. 参照する候補のSHA・全区域の目録・近遠範囲を検査して実行時のindexを置き換える。
5. 実アプリで遅延・欠落・破損・切り替え中断を与え、到着・歩行・飛行・乗車を検査する。
   昼夜・対岸・3居住帯とplaywright-webxr 0.3.0のVR入場・移動・手首UIを確認する。
   固定した同じ配信物で読み込み量と性能を測り、実機未測定を区別する。
